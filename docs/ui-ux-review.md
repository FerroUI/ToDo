# Microsoft To Do comparison and polishing review

Reviewed 22 November 2026 against the public Microsoft references in [the interaction ledger](reference-behavior.md), the deployed application, the Rust implementation, and the browser host. The starting application revision was `257a169263ac77d8220a62cf098d0368e2b13abc`.

The target remains the Windows To Do composition: navigation at the left, a themed list, optional details at the right, and the same destinations presented separately when space is limited. The documentation and screenshots establish workflows and visual hierarchy. They do not establish Microsoft's current private implementation, exact breakpoints, pixel metrics across every release, or authenticated service behavior.

## Combined gesture pass

This pass starts from `19b1e0d4618b11950b49c0d04d42006ff8492ef5` and reviews the boundaries between task actions, scrolling, hold-drag, refresh, and navigation. It keeps the existing Microsoft-reference interaction choices and adaptive pane layout. The fixes concern ownership, cancellation, and recovery rather than adding new gesture commands.

| Combination | Defect or missing guarantee | Correction |
| --- | --- | --- |
| Pending touch then Back/Escape | Cancelling a recognizer before it captured the pointer could leave the native Button pressed, allowing a later release to open a task | Explicit interruption snapshots the live pointers, cancels all app recognition, clears implicit/native capture, and quarantines the contact sequence |
| Wrong-way drawer swipe or edge overscroll | An unsupported movement could become a native Button click when released inside the original row | Rejected shell horizontal movement cancels explicitly; task/sidebar tracks can yield to native scrolling while a tunnel release guard prevents a moved contact from activating the Button |
| Navigation or refresh reversal | Absolute horizontal distance could leave feedback armed after reversing; an invalid release could use previously valid distance | Shared signed progress and axis validation disarm the action when retreating, reversing, or receiving invalid coordinates |
| Drag then route/source change and return | Rechecking only whether the source still existed allowed a stale drag to regain a different meaning | A shared terminal DragOrigin records route, source parent/completion, sorting, width, and appropriate pane state; model notifications invalidate it permanently, including undo/return |
| Hold selection versus layout changes | Entering selection intentionally recycles the source and may close details; unrelated later pane changes must still cancel | Keep capture in the mounted shell and exempt only the hold's initial selection transition; cancel subsequent context/geometry changes |
| Second finger, partial release, third finger | Surviving fingers must not become a fresh action, regardless of release order | Track stable contact IDs and suppress cancelled movement/new contacts until every contact ends, while still delivering native disposal for accepted contacts |
| Touch versus mouse | A second input device could act on the target while interrupting the first | A touch beginning during a native mouse drag cancels the drag and blocks that touch sequence; a mouse press during a live app touch cancels without simultaneously pressing the underlying Button |
| Wheel and dragging | Touch and mouse dragging need different interruption behavior | Wheel cancels app touch gestures; ordinary mouse drag retains wheel scrolling and its validated origin |
| Native drag startup | Win32 reports capture loss during the application's own ReleaseCapture call | Guard only that synchronous transfer before starting native drag; actual later capture loss remains terminal, including inside the OLE message loop |
| Browser Back with a gesture or native editor menu | A transient interaction can exist without a view-model navigation change | Synchronize one same-document Back guard from pending/active gestures, rails, and native flyout opening/closing; first Back cancels the gesture, later Back dismisses the remaining surface |
| Resize, scaling, deactivation, and hidden tabs | Coordinates, timers, markers, and pressed state could survive the interaction surface | Scoped native subscriptions and browser lifecycle callbacks cancel gestures; browser hiding saves drafts after cancellation; blur preserves native editor focus |
| Missed release while inactive | Quarantined raw contacts and native pointer records can survive a lost End event | Only a trusted new primary touch Down may drain interrupted IDs through native cancellation before the new contact is delivered; focus and surviving fingers never reset the sequence |
| Refresh overlapping sync/account changes | Concurrent refresh could fail early while another sync continued; a finishing sync/restore could overwrite Disconnect status | Coalesce concurrent sync promises and serialize account transitions as barriers; failed work releases the queue and refresh completion preserves later navigation/edits |

The browser gate extends the existing touch reviews with combined sequences and stable multi-contact IDs. Its captures and reports distinguish browser-observed behavior from the state/host tests. Physical pen cancellation, OS edge gestures, mobile keyboard behavior, and every native platform remain outside the demonstrated Chromium coverage.

The regression scenarios inspect actual FerroUI layout bounds and native `PART_TextPresenter` ownership. They compare composer centers with its rendered container, compare its columns with actual task controls/text, and verify empty, focused, typed, and recognized-date states at desktop and narrow widths. Existing three-pane checks now verify the same primary-row alignment. Rename checks compare geometry before, during, and after editing, rather than assuming a fixed title or row height. Search and recurrence checks verify the absence of the duplicate clear template part. Populated Suggestions captures and an add/remove round trip cover both desktop and compact layouts.

These scenarios extend the existing browser gate; they add no workflow, browser build, or platform matrix. The application continues to use native WinUI templates, shared Rust controls, reactive drafts, and domain commands. No CSS offsets, HTML replacement editors, or framework-submodule patches are introduced by this pass.

The review also found that the immutable compilation cache key omitted application Rust sources, so a source change could restore old app artifacts under an exact hit and prevent saving their replacements. The key now covers tracked compiler inputs, including embedded assets. App-source timestamp normalization is restricted to a verified exact key match; fallback restores retain fresh application timestamps so Cargo must validate changed sources. Lightweight fixture checks cover source/asset changes, QA-only changes, exact hits, fallback hits, and dirty or mismatched inputs within the existing test gate.

## Architecture and performance review

The six-crate division remains appropriate. Domain commands own persistent changes; the view model owns navigation, selection, transient state, services, and reactive notifications; reusable controls own the WinUI theme/templates; declarative views build the UI; hosts own persistence and platform integration. No parallel DOM task UI was added.

The list still uses one recycling data template over a stable observable source. Row projection excludes large notes and file data. Sort reversal operates on the filtered task references within each completion section and leaves saved manual positions untouched. Selection and rendering use the same ordering. Undo captures affected entities, and each sidebar topology operation remains one transaction. Group dragging reuses the existing cancellation/gesture path instead of introducing a competing input subsystem.

New implementation areas are separated into focused files: sidebar projection/drop planning, sidebar keyboard and emoji handling, scheduling commands, schedule/step menus, custom form validation, sort status, offline bootstrap/manifest generation, and focused regression scenarios. The compiled WinUI theme adds Calendar and ToggleSwitch with their dependencies rather than copying their templates into the app. Touch input remains inside FerroUI gesture recognition and native pointer capture; there is no second JavaScript touch-to-mouse bridge. Swipe motion updates a visual transform without dispatching document edits on each move. Hold-drag reuses the existing live reorder/move planners, drop markers, and bounded edge scrolling, committing at most one domain action on release.

The complete 5,038,236-byte Noto emoji font is a separate integrity-pinned browser asset downloaded in parallel with the runtime and included in the same versioned offline cache. It does not increase the WebAssembly binary. Desktop embeds the same font, while a small shared registration helper keeps networking and host paths out of the reusable controls crate. [Font provenance and license](../crates/todo-controls/assets/fonts/README.md) are recorded with the canonical asset.

CI remains a single build job and dependent Pages deployment job. Small Rust and Node suites validate state/data boundaries; one real-browser gate checks the shipped WebAssembly. There is no platform matrix, duplicate browser build, broad framework test suite, or additional deployment workflow. An exact cache key still identifies the current build inputs; a same-platform, same-framework fallback lets Cargo reuse unchanged framework artifacts when application manifests or compiled template roots change. Cargo remains responsible for dependency and compiler fingerprint validation.

## Adaptive and interaction review

The existing fit-based 760/980-pixel policy is retained. At 320/390 pixels, navigation is a temporary drawer and a selected detail/settings/suggestions surface occupies the main area. The compact detail return arrow points back to the list; the inline detail pane keeps its outward close arrow. At 760/800 pixels, list plus details remain visible and navigation overlays them. At 980/1024 pixels, the 280-pixel sidebar, usable list area, and 340-pixel details coexist. Opening the drawer never squeezes the content underneath it.

The browser gate exercises these widths, list and group pointer movement, keyboard navigation, focused editing, cancellation, menu-to-dialog transitions, native calendar selection, sorting, search return, and persistence. It also sends real browser touch events for tap, horizontal action reveal, vertical scrolling, long-press selection, manual drag across source-row recycling, two-contact cancellation, list/group organization, drawer/Back navigation, and pull-to-refresh. Light, dark, desktop, intermediate, narrow, menu, Calendar, settings, long-detail, compact-help, and touch captures form the visual review evidence. These checks establish the tested Chromium behavior; they are not certification for every physical phone, keyboard, stylus, screen reader, browser, or native operating system.

Independent touch reviews retain separate screenshots, accessibility snapshots, original errors, and a `touch-reviews.json` report. After a failure, normal contact cancellation and page/list navigation prepare the remaining scenarios without injecting a replacement document. Any failed or blocked subgroup still fails the publication gate; later successes include their preceding failures in the report.

Protocol operations have deadlines, and review results are saved incrementally so a stalled browser leaves actionable evidence. The existing browser step also has an eight-minute process limit; a timeout remains a failed gate and the already captured artifacts can still be uploaded. The tab-deactivation case requests a real hidden release, reactivates the original target through the independent browser channel, then requires the release acknowledgement and fresh-input invariants. It does not wait for a hidden renderer's animation frame or substitute a simulated application command.

The gesture arbiter locks to a direction after touch slop. Vertical scrolling cannot later become a destructive horizontal action; swipe release reveals a button rather than immediately editing or deleting a task. A second contact is quarantined until all fingers lift so it cannot become a stray task tap. Pointer cancellation, wheel input, Escape, route change, or removal cancels pending work. Browser Back closes one active surface before traversing a valid prior list; transient renaming cancels, while ordinary note/title/settings edits flush before their surface closes. Refresh updates the local clock and uses the existing serialized account-sync path when connected; it never reloads the document.
